# ปิดงานจองรถอัตโนมัติเมื่อเลยเวลา (Auto-complete booking)

> สถานะ: ดีไซน์ (รออนุมัติ implement)
> วันที่: 2026-07-11
> ขอบเขต: เฟส 4 (Car booking) — เติมพฤติกรรม "ข้อ 7" ที่ยังขาด

## 1. ปัญหา / ที่มา

ปัจจุบันคำขอจองรถ (รถขับเอง) เมื่อ **เลยเวลาสิ้นสุด (`end_at`) ไปแล้วแต่ผู้ใช้ไม่กด "คืนรถ"** จะยังคงสถานะ `approved` ค้างอยู่ และปุ่ม "คืนรถ" ยังแสดงค้างไม่หายไป ระบบไม่มีสถานะ "เดินทางเสร็จสิ้นแล้ว" ตามที่ออกแบบไว้

เป้าหมาย: เมื่อเลย `end_at` ระบบต้องปิดงานให้เป็น "เสร็จสิ้น" อัตโนมัติ ไม่มีปุ่มค้าง และแสดงสถานะที่ถูกต้อง

## 2. หลักการออกแบบ

ใช้สถานะ `completed` (มีอยู่แล้วใน enum) ร่วมกับคอลัมน์ `returned_at` (มีอยู่แล้ว) เป็นตัวแยก "จบงาน 2 แบบ" — **ไม่ต้องแก้ schema**:

| กรณี | status | returned_at | ป้ายที่แสดง |
|------|--------|-------------|-----------|
| ผู้ใช้กด "คืนรถ" เอง | `completed` | มีเวลา (เวลาที่กด) | **"คืนรถแล้ว"** + แสดงเวลาคืนจริง |
| ใช้ครบ/เลยเวลา (ไม่กดคืน) | `completed` | `NULL` | **"เดินทางเสร็จสิ้นแล้ว"** |

กลไกอัปเดต: **lazy sweep ตอนอ่านข้อมูล** (ไม่ตั้ง cron) — ทุกครั้งที่มีการดึงรายการ booking ระบบจะยิง UPDATE เดียวปิดคำขอที่หมดเวลาก่อนส่งข้อมูลกลับ

ขอบเขตการปิดอัตโนมัติ: **ครอบคลุมทั้งรถขับเอง (self) และรถอื่น ๆ (other)**

## 3. รายละเอียดการแก้ไข (4 จุด)

### 3.1 `app/Models/BookingModel.php` — เพิ่มเมธอด `sweepExpired()`

- ยิง UPDATE เดียว: คำขอที่ `status = 'approved'` และ `end_at < ปัจจุบัน` และ `deleted_at IS NULL` → เปลี่ยนเป็น `status = 'completed'`
- **ไม่แตะ `returned_at`** (คงเป็น NULL เพื่อแยกจากการกดคืนรถเอง)
- ต้องระบุ `where('deleted_at', null)` เอง เพราะเป็น bulk update
- เรียกที่ต้นเมธอด list ทั้งสาม: `listForUser` (User), `listAll` (Admin), `listForDriver` (Driver) → ทุก role เห็นสถานะตรงเสมอโดยไม่ต้องพึ่ง cron

### 3.2 `app/Controllers/User/BookingController.php` — `returnCar()` กันคืนรถหลังหมดเวลา

- เพิ่มการ์ด: ถ้า `end_at <= ปัจจุบัน` → ไม่อนุญาตคืนรถ ตอบ `fail('การเดินทางสิ้นสุดแล้ว')`
- สอดคล้องกับ "เลยเวลาแล้วต้องไม่มีปุ่มให้ทำรายการ" และกันการยิง API ตรง

### 3.3 `resources/js/islands/MyRequests.jsx` — การแสดงผล + ปุ่ม

- ปุ่ม "คืนรถ" แสดงเฉพาะช่วง **ถึงเวลาเริ่มแล้วแต่ยังไม่เลย `end_at`**:
  `showReturn = approved && started && !ended && booking_type === 'self'`
  (`ended = new Date(end_at) <= now`)
- คำขอที่ `approved` แต่เลย `end_at` แล้ว (ยังไม่ถูก sweep) → แสดงเป็น **"เดินทางเสร็จสิ้นแล้ว"** ทันทีฝั่ง client (UI ถูกต้องแม้ก่อน sweep จะ persist)
- ป้ายสถานะ `completed`: ถ้ามี `returned_at` = "คืนรถแล้ว" (พร้อมบรรทัดเวลาคืน), ถ้าไม่มี = "เดินทางเสร็จสิ้นแล้ว"
- สี/ถ้อยคำป้าย "เดินทางเสร็จสิ้นแล้ว": โทนเทา-ฟ้ากลาง ๆ `bg #eef2f4 / text #5b6b7a`

### 3.4 `resources/js/islands/RequestsManager.jsx` (Admin) — ป้ายให้แม่น

- เพิ่มเงื่อนไข: `completed` + ไม่มี `returned_at` → แสดง "เดินทางเสร็จสิ้นแล้ว" (ไม่งั้นใช้ "คืนรถแล้ว" เดิม)
- เป็นการแก้ **เฉพาะข้อความ/สี ไม่แตะ logic** — สถานะ `completed` หน้า Admin รองรับครบอยู่แล้ว (ป้าย/ตัวนับสรุป/ฟิลเตอร์/บรรทัดเวลาคืน)

## 4. สิ่งที่ไม่ทำ (นอกขอบเขต)

- ไม่ตั้ง cron / scheduled task
- ไม่แก้ schema ฐานข้อมูล (enum `completed` + คอลัมน์ `returned_at` มีอยู่แล้ว)
- ไม่แตะ logic กันจองซ้อนเวลา (overlap) — ทำงานถูกต้องอยู่แล้ว (อิงช่วงเวลา คำขอในอดีตไม่บล็อกการจองอนาคตอยู่แล้ว)
- หน้า Driver "งานของฉัน" ยังเป็น placeholder (ไม่มี island) — ไม่กระทบ

## 5. ผลกระทบ / ความเข้ากันได้

- สถานะ `completed` **มีอยู่ในระบบแล้ว** (เกิดจากการกด "คืนรถ" ตั้งแต่เฟส 4) หน้า Admin จึงรองรับอยู่แล้ว การ sweep แค่ทำให้มี `completed` เพิ่มขึ้น ไม่เพิ่มชนิดสถานะใหม่
- ผลต่อ Admin: คำขอที่ปิดอัตโนมัติจะโผล่ในหน้า Admin ด้วย ป้ายถูกปรับให้แสดง "เดินทางเสร็จสิ้นแล้ว" (§3.4)

## 6. การทดสอบ (E2E)

1. จองรถขับเอง (self) เวลาสั้น ๆ → admin อนุมัติ → ก่อนถึงเวลาเริ่ม เห็นปุ่ม "ยกเลิกคำขอ"
2. ถึงเวลาเริ่ม (ยังไม่เลย end) → ปุ่มเปลี่ยนเป็น "คืนรถ"
3. กดคืนรถก่อนหมดเวลา → สถานะ "คืนรถแล้ว" + มีเวลาคืนจริง (returned_at) → รถจองต่อได้
4. อีกคำขอหนึ่ง ปล่อยจนเลย `end_at` โดยไม่กดคืน → โหลดหน้าใหม่ → สถานะ "เดินทางเสร็จสิ้นแล้ว" + ไม่มีปุ่ม + DB เป็น `completed` และ `returned_at = NULL`
5. ยิง `returnCar` ตรงหลังเลย end → ถูกบล็อก "การเดินทางสิ้นสุดแล้ว"
6. หน้า Admin: คำขอข้อ 4 แสดงป้าย "เดินทางเสร็จสิ้นแล้ว"; คำขอข้อ 3 แสดง "คืนรถแล้ว"
7. ทำซ้ำกับรถอื่น ๆ (other) ที่อนุมัติแล้วเลยเวลา → เป็น `completed` (เดินทางเสร็จสิ้นแล้ว)

## 7. ขั้นตอน build

หลังแก้ JSX ต้อง `npm run build` (โหมด prod `vite.dev=false`) เพราะ asset โหลดจาก `public/build`
